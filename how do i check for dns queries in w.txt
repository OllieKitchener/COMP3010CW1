To identify **DNS (Domain Name System) queries** in Wireshark, DNS traffic typically uses **UDP port 53** for most queries and responses, while **TCP port 53** is occasionally used for larger payloads (e.g., zone transfers). Here's how to filter and analyze DNS traffic:

---

### **Step-by-Step Guide to Filter DNS Queries in Wireshark**
#### **1. Open Your Wireshark Capture File**
- Launch Wireshark and load the relevant PCAP file (e.g., `capture.pcap`).

---

#### **2. Apply a Display Filter**
Use a filter to isolate DNS-related packets. Here are common options:

### **Option 1: Basic DNS Traffic (UDP/TCP on Port 53)**
This captures **all DNS-related packets** (queries and responses):
```plaintext
port 53
```
- **In Wireshark:**
  1. Click the **Filter** button (top-left) or go to **View > Show/Hide > Filter**.
  2. In the filter bar, type `port 53` and click **Apply**.
  3. All DNS packets (UDP/TCP on port 53) will now be displayed.

---

### **Option 2: Only DNS Queries (Not Responses)**
This isolates **DNS queries** (requests from your device to a DNS server):
```plaintext
DNS query
```
- **In Wireshark:**
  1. In the filter bar, type `DNS query` and click **Apply**.
  2. This will show only packets where the role is a **query** (e.g., `A`, `MX`, `CNAME` records).

---

### **Option 3: Combine Both Protocols Explicitly**
To ensure both TCP and UDP are included, you can use:
```plaintext
tcp port 53 or udp port 53
```
- **In Wireshark:**
  1. Type `tcp port 53 or udp port 53` in the filter bar and click **Apply**.

---

### **Option 4: Filter by Source or Destination IP**
If you want to see DNS queries from a specific IP (e.g., your local machine):
```plaintext
src == [Your_IP Address] and port 53
```
- Replace `[Your_IP Address]` with your device’s IP (e.g., `192.168.1.100`).
- This shows DNS queries sent **FROM** your IP to a DNS server.

---

### **3. Analyze the Results**
- **Sort Packets**:
  - Click the **Protocol** column header to group DNS packets together.
  - Sort by **Time** to see chronological order.
- **Packet Details**:
  - Click a DNS packet to view the **DNS Query/Response** details (e.g., `Query: A record`, `Response: AAAA record`).
  - Look for fields like **Type** (e.g., `A`, `CNAME`, `NS`), **Class** (e.g., `IN`), and **Value** (e.g., IP address or domain name).

---

### **Key Notes**
- **UDP vs. TCP**:
  - Most DNS queries/responses use **UDP (port 53)**.
  - TCP is rare for standard DNS but may appear for large requests (e.g., zone transfers) or when DNS is encrypted with TLS (though rare).
- **Decrypted Traffic**:
  - If your capture is encrypted (e.g., DNS over TLS), ensure Wireshark is decrypting traffic first. Go to **Statistics > Decryption** to check.
- **Common Use Cases**:
  - **Queries**: `www.google.com` → `8.8.8.8` (A record).
  - **Responses**: `8.8.8.8` → `www.google.com` (NS record or CNAME).

---

### **Example Filter for Local DNS Queries**
Suppose your device has an IP of `192.168.1.100` and you want to see DNS queries it sends to a DNS server:
```plaintext
src == 192.168.1.100 and port 53
```

---

### **Command-Line Filter (Wireshark CLI)**
To run Wireshark with a filter directly in the terminal:
```bash
wireshark -i "port 53" -r capture.pcap
```
Or for queries only:
```bash
wireshark -i "DNS query" -r capture.pcap
```
