### **Method 1: Using Wireshark's OS Class Column (TCP Packets)**
1. **Open your network capture** in Wireshark.
2. **Filter the display** to focus on traffic from the infected system's IP address:
   - Go to the **Filter** menu (top-right) and enter a display filter like:
     ```
     ip.addr == "X.X.X.X"       # Replace "X.X.X.X" with the infected host's IP
     ```
3. **Select a TCP packet** from the infected system (e.g., a SYN or ACK packet).
4. **Right-click the TCP packet** in the main window and choose **Dissect** to open the **Dissection Pane**.
5. In the **Dissection Pane**, look for the **"OS Class"** or **"OS Class"** column (varies by Wireshark version). It may show:
   - The **name** of the OS (e.g., "Windows 10," "Linux," "macOS").
   - A **probability percentage** (e.g., "Windows 10 – 85%").
6. **Interpret the result**: A higher probability (e.g., 85%) for Windows, 100% for Linux/OS X, etc.

### **Method 2: Analyzing DNS Queries**
If TCP dissecting isn’t sufficient, inspect **DNS queries**:
1. Filter **DNS traffic** (tcp.port == 53 or udp.port == 53).
2. Check the **target DNS server** (e.g., if the infected host is querying `8.8.8.8` for DNS resolution, this could hint at Windows).
3. **Common DNS resolvers**:
   - `8.8.8.8` (Google DNS): Often used on Windows.
   - `1.1.1.1` (Cloudflare) or `1.1.1.1`: Common on Linux/OS X systems.
   - `Cloudflare` or custom resolvers may indicate pre-configured OS settings.

### **Method 3: HTTP/HTTPS Traffic Analysis**
If the infected system is making HTTP requests:
1. **Filter HTTP traffic** (tcp.port == 80 or https traffic if HTTPS).
2. **Check headers**:
   - Look for **User-Agent strings** in HTTP headers (e.g., `Mozilla/5.0` for Windows, `Safari` for macOS, `Chrome` for Android/iOS).
   - Observe **HTTP headers** like `User-Agent` or `Accept` strings, which often include OS-specific identifiers.

### **Method 4: TCP Protocol Analysis**
1. **Examine TCP traffic** (ports 80/TCP, 443/TCP for HTTPS):
