In Wireshark, **SMTP (Simple Mail Transfer Protocol)** and **TCP** use specific port numbers to identify their traffic. Here's a breakdown:

---

### **1. SMTP Ports**
SMTP uses **TCP ports** to communicate over the internet or a network. The most common ports are:

- **Port 25**:
  The **traditional, non-encrypted** SMTP port for sending and receiving email messages.
  Example: `smtp://example.com:25`

- **Port 465 (SMTPS)**:
  The **encrypted** version of SMTP (SMTP over SSL/TLS).
  Example: `smtps://example.com:465`

- **Port 587 (submission)**:
  Another **encrypted** SMTP port often used for email submission (common in modern setups due to reduced spam filtering requirements).
  Example: `smtp://example.com:587`

---

### **2. TCP Ports**
TCP (Transmission Control Protocol) is the **transport layer protocol** that carries data between devices. It doesn’t have a single "SMTP port" but uses port numbers to identify services. The above SMTP ports (25, 465, 587) are **TCP ports** used for SMTP communication.

- **TCP is agnostic to the application layer**—it simply provides a connection between two devices. The specific port (e.g., 25 for SMTP) defines *which service* is being used over TCP.

---

### **3. How to Identify These Ports in Wireshark**
#### **A. Display Filter Syntax**
Use Wireshark’s **display filters** to isolate SMTP or TCP traffic on specific ports:

1. **To show all SMTP packets (any port)**:
   ```plaintext
   protocol:smtp
   ```
   This matches any packet with the SMTP protocol, regardless of port.

2. **To show only SMTP traffic on Port 25**:
   ```plaintext
   protocol:smtp and tcp port == 25
   ```
   Replace `25` with your target port (e.g., `465` or `587`).

3. **To show all TCP traffic on a specific port (e.g., Port 25)**:
   ```plaintext
   tcp port == 25
   ```

#### **B. Column Headers**
In Wireshark’s main window:
- The **"TCP Port" column** displays the destination port for TCP packets.
- The **"Protocol" column** shows the service (e.g., "SMTP" or "TCP").

You can **sort by these columns** to quickly spot activity on specific ports.

---

### **4. Example Use Cases**
- **All SMTP traffic (encrypted or not)**:
  Use `protocol:smtp` in the filter bar.

- **SMTP with TLS on Port 587**:
  Use `protocol:smtp and tcp port == 587` to capture encrypted SMTP traffic.

- **Unencrypted SMTP (Port 25)**:
  Use `protocol:smtp and tcp port == 25` to see raw SMTP data (not recommended for untrusted networks due to security risks).

---

### **Key Notes**
- **SSL/TLS Decryption**: If you’re analyzing encrypted traffic (e.g., Port 465/587), ensure the capture file is decrypted first.
- ** direction**: Use `src == [IP]` or `dest == [port]` to focus on traffic from/to a specific device or port.
- **Common Misconceptions**:
  - SMTP ≠ HTTP/HTTPS: HTTP uses Port 80, HTTPS uses 443.
  - Port 25 is still widely used but may be blocked by some email servers due to spam concerns (hence Port 587’s popularity).
